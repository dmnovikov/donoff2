# Разбор donoff-lib (ветка newlife32) для donoff2

Предложения из этого разбора приняты 2026-11-10.
Весь код прочитан; что перенесено и что нет — в разделе «Итог переноса» в конце.

## Команды: установка `name=value`

`;` в конце сохраняет в EEPROM.

| Команда (синонимы) | Диапазон | Что делает | donoff2 |
|---|---|---|---|
| `aofs` (`aofs1`) | 0..1200 с | автоотключение реле 1 / полив | оставить |
| `aofs2` (`a2ofs`) | 0..1200 с | то же, реле 2 | оставить |
| `lschm` (`lschm1`, `schm1`) | 0..100 | расписание реле 1 | оставить, запретить 21..24 |
| `lschm2` (`l2schm`, `schm2`) | 0..100 | расписание реле 2 | оставить, запретить 21..24 |
| `cschm1`, `cschm2` | час:0/1 | свои схемы 99 и 100 | оставить |
| `om1`, `om2` | 24 бита | матрица часов целиком | оставить |
| `hotter` (`h`) | 0..255, значимы 0, 1, 2 | нагрев: 1 день/ночь, 2 матрица по часам | оставить |
| `cooler` | 0/1 | охлаждение | оставить |
| `ctempl`, `dtempl`, `ntempl` | −5000..10000 | уставка обычная, дневная, ночная | оставить, старые единицы тоже |
| `tdelta` | 0..50000 | гистерезис | оставить, старые единицы тоже |
| `tmatrix` | | уставка на каждый час (для `hotter=2`) | оставить |
| `onoffschm1`, `onoffschm2` | 0..100 | какая схема задаёт день и ночь | `1` оставить, `2` не используется |
| `tz` | −15..15 | часовой пояс (обработчик продублирован с −12..14) | оставить один |
| `autoreboot` | 0/1 | перезагрузка после 100 неудачных подключений | оставить |
| `baselog` | 0/1 | JSON в топик базы, у датчиков `NEED_BASELOG` по умолчанию 0 | убрать, историю ведёт панель |
| `tariff` | 0..10000 | только хранится и отдаётся, логики нет | убрать |
| `clevel1`..`clevel4` | ±32000 | смысл зависит от платы, см. ниже | оставить как имена, смысл задаёт класс платы |
| `onoffv1`, `onoffv2` | | помечены устаревшими | убрать |
| `testbool`, `testint` | | тестовые | убрать |
| `notifyer`, `notifyonoff`, `notifyhours`, `ltempnot`, `htempnot`, `anotify1/2`, `cnotify1..4` | | уведомления | убрать, ответ `E:` |

| Команда | Что делает | donoff2 |

| `save` | сохранить настройки | оставить |

## Запросы `sh`

Кроме параметров выше: `schma`, `schma1`, `schma2`, `tlevels` (`tls`), `hot`, `r1`, `r2`,
`time`, `dinfo`, `email`, `net`, `ip`, `pinset`, `cmpl`. В donoff2 все остаются, плюс `sh all`.

## Объявлены, но обработчика в publishers нет

`synced`, `salt`, `bschm`, `sendalive`, `zeroalarm`, `clear`, `setdefault`, `resetucounter`,
`bbschm1`, `bbschm2`. В supply могут быть, проверить. Команды `aofh` в этой ветке нет,
поле `autooff_hours` и `aofh_loop` остались без управления.

## Датчики

DS18B20 (внутр./внешн.), DHT, SCT013 (один, несколько, 3 фазы), ADS1115, PZEM004,
MAX44003, `mera`, виртуальный `temp_odds`.

## Прочее

- Кнопка: короткое нажатие переключает реле, долгое открывает портал, очень долгое перезагружает.
- Топики: см. протокол, `time_up`, `time_comm`, `time_down` остаются.
- Без времени: схемы 1 и 2 работают, остальные нет; `hotter=2` и день/ночь берут `ctempl`.
- Дисплей SSD1306: есть в `donoffdisplay.h`.
- Проектные supply: насос (`pump_current_time_check`), `6temp`, `temp_odds`.

## Ограничение долгой нагрузки (`strong_sec`)

`supplies/prj_supplies/pump_current_time_check_supply.h`, класс `DSupplyDonoffUniCurr`:

- `clevel1` — порог тока, А×100 (0 — функция выключена; не задано — 1 А).
- `clevel2` — сколько секунд ток может быть выше порога (не задано — 3600).
- Ток выше порога: идёт таймер. Ток ниже или равен порогу: таймер сбрасывается.
- Топик `/out/sensors/strong_sec` — текущее время превышения в секундах.
- Время вышло: `lschm2=1` (всегда выкл.) для реле 2 и сообщение `strong_curr: off, current strong time` в info.

Что не так: `lschm2=1` не сохраняется, после перезагрузки или отключения света нагрузка снова
включится по старому расписанию. Сообщение повторяется, пока ток не упадёт.

В donoff2: отдельный класс-ограничитель, правило «значение, порог, секунды, реле» подходит к любому
значению из таблицы (ток, мощность PZEM, температура). `strong_sec` — виртуальное значение таблицы,
топик тот же. Срабатывание сохраняется и публикуется один раз.

|---|---|---|---|---|
| Насос с контролем тока | порог тока | секунды | | |

## Длинные циклы

`one_minute_loop`, `ten_minutes_loop`, `thirty_minutes_loop`, `one_hour_loop` объявлены в `DSupply`
пустыми, и ни один класс в репозитории их не переопределяет: не используются. Сейчас всё расписание
построено на счётчиках `mycounter` и `mycounter2`. В donoff2: простой планировщик задач с периодом,
длинные циклы не переносим.

## Решения


1. Убрать `tariff`, `ucounter`, `baselog`, `urgent_off`, `current_check`, `weekschm`, `autooff_hours2`, `onoffschm2`.
2. `aofh`: убрать вместе с `autooff_hours` и `aofh_loop`, функция не используется, её перекрывает схема `lschm`.
3. Датчики переносить по очереди: DS18B20, SCT013, PZEM (стоят на живых устройствах), потом остальные по мере надобности.
4. Дисплей SSD1306: на потом.

## Итог переноса

Платы (окружения `platformio.ini`): `d1_mini` (V1), `v2`, `v3`, `single`, `current`, `pump`, `ds2`, `tempodds`,
`dht`, `ads`, `lux`, `bh1750`, `bh1750_1r`, `bme280`, `bme280_1r` (BH1750 и BME280 новые, в donoff-lib их не было;
`_1r` — одно реле, SCL на D6), `pzem`, `sct013`, `sct013x3`, `temps5`, `display`, `esp32r4`.

Не перенесено намеренно:

- `sensors/donoffsensor_mera.h` — копия SCT013, нигде не подключена.
- `start_on` — в старом коде закомментирован.
- OTA в donoff-lib нет, в donoff2 пока тоже.
- Modbus RTU: в старом коде его нет, параметры порта хранятся, класс `DOutputModbus` готов к RTU.

Исправлено по сравнению со старым кодом:

- DHT: температура читалась из поля влажности и всегда была NaN.
- 6temp: создавалось 5 датчиков, плата называется `temps5`.
- PZEM, ADS1115 и MAX44009 без внешних библиотек; PZEM и ADS1115 не ждут ответа в `loop()`.
- Портал не останавливает термостат и расписания, пароль MQTT в нём не показывается.
- Точка доступа портала с паролем (`DONOFF_AP_PASSWORD`, по умолчанию `donoff2setup`).

## Датчики I2C

Общий класс `DSensorI2C`: шина, один или два адреса на выбор, чтение и запись регистров, повторный поиск
потерянного датчика. В лог один раз на изменение: `N:<имя> ok, addr 0x.. sda= scl=` или `E:<имя> i2c error N`
(2 — нет ответа по адресу, 5 — шина прижата к земле, 8 — по адресу отвечает другой чип, 9 — чтение не вернулось).
На нём BH1750 (0x23/0x5C), MAX44009 (0x4A/0x4B), ADS1115 (0x48), BME280 (0x76/0x77, id 0x60) и BMP280 (id 0x58, без влажности: `bme_humidity` = −127).

Пины шины: по умолчанию SDA D2 (GPIO4), SCL D7 (GPIO13), у ADS1115 как в donoff-lib (SDA GPIO13, SCL GPIO4).
Настройки `i2csda`, `i2cscl` (−1 — как у платы) меняют их после `reset`. Пин, занятый на плате реле,
кнопкой, светодиодом, DS18B20 или другой линией шины, отклоняется (`E:pin busy`), как и GPIO6..11 и GPIO16
на ESP8266. `sh i2c` — пины, на которых шина сейчас.

## Modbus TCP

Только чтение. Включается `mbtcp=1`, порт `mbport`, адрес `mbunit` (принимается и 255).

| Что | Функция | Адрес |
|---|---|---|
| состояние времени (0 нет, 1 есть, 2 устарело) | 03, 04 | 1 |
| аптайм, секунды, старшее и младшее слово | 03, 04 | 2, 3 |
| реле N | 01, 02 | N−1 |
| значение датчика | 03, 04 | `reg` старшее, `reg+1` младшее (со знаком, значение × `mult`), `reg+2` состояние (0 не готов, 1 норма, 2 ошибка) |

`reg` и `mult` каждого датчика есть в `out/meta`.

| Датчик | `reg` | Датчик | `reg` |
|---|---|---|---|
| `temp_in` | 10 | `pzem_current`, `_power`, `_voltage`, `_energy` | 30, 33, 36, 39 |
| `temp_out` | 13 | `dht_humidity`, `dht_temp` | 42, 45 |
| `temp_out2` | 16 | `lux` (MAX44009 или BH1750) | 48 |
| `temp_odd` | 19 | `ads0`..`ads3` | 51, 54, 57, 60 |
| `current`, `sct013_1` (одиночный) | 22 | `sct013_1`..`_3`, `sct013x3` | 63, 66, 69, 72 |
| `strong_sec` | 25 | `temp1`..`temp5` | 75, 78, 81, 84, 87 |
| | | `bme_temp`, `bme_humidity`, `bme_pressure` (гПа) | 90, 93, 96 |
